# 1장 완성 중심 재계획

2026-10-31 보완: 사용자의 SACRATA 영상 분석 확인 요청에 따라 C0의 영상 검토를 다시 열었다. 초안 계획은 있으나 **참고 영상 분석 전체 완료는 아니다**. 최신 직접 관찰과 한계는 `SACRATA-VIDEO-REVIEW.ko.md`, `BROWSER-PLAY.ko.md`를 따른다. SACRATA가 최종 표현·전투 품질 기준이며 D2 Survivors의 성장 구조를 확인한 것으로 이를 대체하지 않는다. 새 제품 구현은 아직 시작하지 않았다.

2026-10-30, Asia/Seoul. 상태: 계획 재점검 완료·구현 미착수. 기존 기술 승인과 별개로 사용자가 현재 게임 품질을 부적합으로 판정한 사실을 출발점으로 삼는다. 기존 코드·원작·실행본·성공/실패 증거·사용자 저장은 보존한다.

## 1. 목표를 고정한다

**SACRATA를 지향하는 시각적 완성도와 화려한 군중 전투에, 디아블로식 장비 드롭·선택·스킬 성장·빌드 조합의 재미를 결합한 1장을 완성한다.**

플레이어 경험: 약한 공격으로 시작 → 반복 선택과 드롭으로 전투 방식 변화 → 커진 공격으로 무리를 휩쓸기 → 정예/목적지를 공략해 핵심 보상 획득 → 완성한 빌드로 보스 공략 → 보상 확인·저장·다른 빌드로 재도전.

1장은 시작·전투·성장·탐색·장비·정예·보스·승패·보상·저장이 연결된 독립적인 한 장이다. 대표90초는 이 장을 만들기 위한 중간 품질 관문이며, 1장의 범위를90초로 축소하는 뜻이 아니다. 1장의 제품 품질이 통과하기 전에는2·3장 콘텐츠를 만들지 않는다.

기본 환경은 현재 Godot4.5.1/GDScript/Windows/Forward+를 유지한다. 새 엔진 전환을 전제로 하지 않는다. 사용자가 **5–8분의 짧고 밀도 높은 첫 장**과 **https://d2survivors.lol/**을 참고 대상으로 확정했다. 정상 완주 목표는6분 전후이며, 짧은 성장 선택·장비 비교·보스·보상 정리까지 포함해5–8분에 들어오도록 설계한다. Esc/이탈 등 장기 정지는 별도 집계한다. 과거10–15분 가정은 폐기했다.

## 2. 참고작이 맡을 역할

|---|---|---|

자료 식별: 사용자가 선택한 참고작은 **framara의 [d2survivors.lol](https://d2survivors.lol/)**이다. [zombodotcom 빌드 저장소](https://github.com/zombodotcom/d2survivors-releases)는 선택된 참고작이 아니며 비교용 보조 자료로만 남긴다. 두 주체의 관계는 확인하지 못했다. 사용자의 REA 활용 설명은 공개 자료에서 구체적인 복원 범위를 확인하지 못한 상태로 유지하며, REA를 사용하지 않았다는 결론도 내리지 않는다.

D2Survivors 공식 [시작하기](https://d2survivors.lol/wiki/getting-started/)에서 확인한 연결은 자동 시전→경험치 보석 회수→레벨3지선다→기술 습득/강화→정예·보스 상자와 진화→장비 보존이다. 문서는 막당6분과 막 보스를 설명하므로 사용자의5–8분 범위와 비교하기 적합하다. 이는 문서 확인이며 실제 조작·내부 코드·성능 검증과 구분한다. 직접 플레이 관찰은 별도 기록으로 보완한다. 다른 동명 저장소의 추가 투사체/proc/장비 비교 등은 별도 보조 아이디어로 구분하고 이 사이트에서 확인한 사실로 인용하지 않는다.

기존의 보호되는 원작 자산을 제품에 복사하지 않는 경계를 유지한다. 참고작의 로컬 게임 파일 읽기 방식을 이번 제품의 자산 공급 방식으로 자동 채택하지 않는다. 새 제품의 모델·애니메이션·효과·음향은 출처와 사용 조건을 확인한 자산 또는 독자 제작물로 확보한다.

## 4. 전투와 성장의 실제 설계

### 군중 전투의 리듬

짧은 압박 → 위치/공격 선택 → 한 무리의 폭발적 처리 → XP·드롭 회수 → 새 선택 → 더 큰 압박의 반복을 만든다. 상시 소수 적 또는 모든 적의 과도한 체력으로 대신하지 않는다. 약한 적·위험한 적·정예의 비중을 조절해 몹을 휩쓸면서도 위험은 읽을 수 있게 한다.

초안 밀도는 초기20–50/중반50–100/후반80–150 동시 활성, 짧은 폭발 구간150–300을 탐색 범위로 삼는다. 이는 현재 달성한 일반 플레이 수치나 무조건 고정할 스폰 수가 아니다. 새 아트·스킬·드롭이 함께 있는 대표 장면의 성능과 위험 가독성으로 확정한다. 정상 플레이의 수·처치율·대기시간·이동 목적을 측정하고, 300적 합성 성능과 분리한다.

### 기술과 장비는 플레이 방식을 바꾼다

- 화염: 단발→관통 또는 폭발 범위→점화/처치 폭발이라는 성장 축을 검토한다.
- 냉기: 감속→빙결/파편→무리 제어와 파쇄라는 성장 축을 검토한다.
- 번개: 단일 타격→연쇄/분기→다수 적 연속 처치라는 성장 축을 검토한다.
- 기술 설명·화면·판정·장비 효과·피해 trace가 일치해야 한다. 위 효과는 구현된 사실이 아니라 신규 설계 후보다.
- 세 기술을 키로 번갈아 누르는 것에 머무르지 않고, 자격을 얻어 장착한 기술들이 각자 주기/조준 규칙으로 자동 시전되는 구조를 설계한다. 수동 조준/특수 회피는 선택 가능하되 기본 경험은 이동·성장 선택·군중 처리에 집중한다.
- 장비 옵션은 피해·치명타·속도만 아니라 투사체 수/관통·연쇄·조건부 발동 등의 형태 변화를 포함한다. 추가 발동은 출처·대상·쿨다운·1회 예산·재귀 깊이를 명시해 무한 연쇄를 막는다.
- 레벨 선택3개는 상한/선행 조건/중복을 검증한다. 도달 불가능한 진화나 이미 꽉 찬 선택만 나오는 상태를 막고, 같은 선택 전후의 화면을 비교해 체감 차이를 확인한다.

### 드롭의 기대와 선택

적/보상 원천→드롭 여부/base 후보→품질→자격을 만족한 옵션/고유효과→아이템 instance→비교/장착→공격 변화로 이어지는 명세를 만든다. 모든 원작 TC를 모사하는 것이 목표는 아니다. 독립적으로 단순화한 부분과 근거를 남긴다. 레벨별 후보·배타 그룹·중복/값 범위·옵션 가중치·상한을 데이터로 검증한다.

초반 유효한 업그레이드, 중반 빌드 방향의 선택, 후반 핵심 옵션을 노릴 이유가 있어야 한다. 현재 장착품과의 비교는 단일 점수/녹색 화살표뿐 아니라 포기하는 능력과 얻는 기술 효과를 보여 준다. 경험치·자원은 빠르게 수집하고, 장비는 이름표/등급 신호/필터로 무리 전투를 가리지 않도록 한다. 인벤토리 확인은 안전한 정지 상태에서 가능해야 한다.

## 5. 연구와 제작을 연결한다

각 조사 단위는 `질문→버전·원문 위치→확인/미확인→독립 채택 규칙→변경 이유→플레이 검수`로 닫는다. 현재 D2R3.3.93847 기록·별도 CASC 추출·고정 D2MOO1.10f·정상 관찰·독립 설계를 계속 구분한다.

우선 질문은 옵션 자격·그룹·가중치, base/품질/레벨의 관계, 스킬 투자/장비 레벨/시너지 적용 범위, 피해/저항/속도의 선택 관계다. 기존 표·고정 참조·정상 관찰에서 답을 찾은 후 필요한 특정 함수에만 REA를 사용한다. 핵심 함수나 자료가 없는 질문을 현재 D2R 확인 사실로 채우지 않는다. 전체 엔트리 시간초과와 같은 조건을 반복하지 않는다. 조사 중단 시 미확인 원작 규칙과 명시적 자체 선택을 구분하여 독립 구현을 진행한다.

아트는 실제 공급 작업이다. 캐릭터/적의 조형·리그·애니메이션, 환경 모듈/재질, VFX의 형태와 타이밍, UI 아이콘, 음향/음악을 각각 확보·제작·통합·청취·검수해야 한다. 현재 KayKit 기술 대역을 계속 색칠하는 것만으로 최종 품질을 충족했다고 처리하지 않는다. 자산 후보의 실제 원본과 라이선스, 리그·클립 적합성, 가격/보유 권한, 엔진 가져오기 결과를 비교한다. 유료 결제는 후보와 비용이 구체화된 뒤 별도 승인 대상이며 이번 계획에서 구매하지 않는다.

## 7. 운영과 인계

- 단계마다 현재 제품·문서·원본 사용자 저장의 별도 백업과 hash를 만든다. 기존6/7단계 후보·사용자 저장·841개 역사 guard·실패 원시를 보존한다.
- 새 1장 저장은 별도 versioned 프로필로 설계한다. 기존 equipment-v1/progress-v1을 자동 변환/덮어쓰지 않는다. 가져오기 기능이 필요하면 별도 명시적·검증 가능한 작업으로 계획한다.
- 구현 담당→독립 검증→코드 검토→실제 플레이·품질 검수 순서. 연구/아트 자료 수집은 병행할 수 있으나 제품의 근거와 불확실성은 분리한다.
- 사용자 보고는 검사 개수보다 장면/빌드/드롭/위험/성장 전후의 변화와 남은 차단사항을 먼저 보여 준다. 기술 기반 완료와 제품 품질 완료를 별도로 표시한다.
- 소유 프로세스·출력 위치·도구/API는 새 작업 때 다시 확인한다. 커밋/외부 업로드/유료 자산 구매를 자동 수행하지 않는다.
