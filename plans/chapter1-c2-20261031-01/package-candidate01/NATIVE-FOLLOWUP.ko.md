# 후보01 실제 OS 검수 후속 — 수정 필요

부모가 PID13512의 실제 창을 조작했고 이 담당자는 입력하지 않았다. 부모 관찰: 마우스 시작·성장 선택·결과의 다시 도전 버튼은 작동했다. choice에서 Escape 두 번, defeat에서 R 입력은 보이는 변화가 없었다. 키 이벤트의 원인은 별도 입력 observer로 확인하기 전 단정하지 않는다.

첫 판은 거의 제자리인 입력 검수 중 14.283333초·44처치·레벨4·소유 장비2개에서 패배했다. raw log의 실제 HP는0이지만 부모가 본 HUD는5/120으로 남았다. `cloister_hud.gd`는 모드 변경으로 결과창을 다시 만들더라도 동일 tick의 6tick HUD 갱신 제한에 걸릴 수 있으므로 수정/독립 재검증이 필요하다. 이 판을 일반 사용자 밸런스 평가로 해석하지 않는다.

마우스 재도전은 새 판 약7초·7처치·레벨2까지 부모가 확인했다. 이전 frame-005.png를 같은 이름으로 캡처하려 하자 덮지 않고 거절한 ERROR가 로그에 남았다. 이는 앞서 보고한 QA 출력 이름 한계이며 기존 PNG는 보존됐다.

정상 창 X 닫기는 actualexit0이다. `native-menu-exit.json`의 실제 벽시계는244.229932초이며 중간 정지/모달 시간을 포함한다. 이번 로그에서 음향 shutdown 경고는 발견되지 않았다. 실제 청취 승인은 아니다.

후보01 EXE·stage·PCK·PNG·로그·검토 문서는 변경하지 않는다. 새 수정은 `native-fix02`와 별도 후보02로 이어간다. 이 후속 발견에 따라 후보01의 실제 입력/HUD 검수는 미완료이며, 앞선 코드 검토의 '추가 차단 발견 없음'은 실제 OS 검수 이전 시점의 결과다.
