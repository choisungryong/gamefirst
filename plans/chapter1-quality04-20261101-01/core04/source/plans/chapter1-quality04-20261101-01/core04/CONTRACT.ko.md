# 코어04 군중 접근 계약

2026-11-01. 기존 `chapter1/core/COMBAT-RUN.ko.md`는 코어03 이력으로 보존한다. 이 문서는 후속 코어04에서 바뀐 접근 규칙과 검증 범위다. 군중 규칙이 실제 위치·조우·회수·공격 시점을 바꾸므로 코어03과 전체 상태의 bitwise 일치를 주장하지 않는다.

- 고정60Hz, 반폭19m, UID/generation, HP·XP·성장·장비·드롭·공격 피해/전조 크기·발동/회복 시간·대시 경계·보상 상한은 기존 의미를 유지한다. 코어는 프로필을 읽거나 쓰지 않는다. 표현은 피해/보상을 만들지 않는다.
- 접근 상태 `move`에서만 주변 몸체 압력을 더한다.2m 격자9칸을 정해진 순서로 조회하며 자기 자신을 제외한 **최대32개 몸체를 검사**한다. 검사한 몸체 중1.85m 이내가 영향을 준다. 격자와 순회는 UID 오름차순이며 중첩 위치의 분리축도 두 UID로 결정한다. RNG를 소비하지 않는다.
- 목표 몸체 간격은 두 반경 합+.08m다. 압력 보정은 tick당.045m 이하이고 최종 접근 변위는 `현재 감속을 적용한 speed/60+.045m` 이하다. 위치는 항상±19m에 제한한다. 이는 물리 강체 충돌/벽 내비게이션이 아니며 모든 겹침0을 보장하지 않는다. 밀집/상한/고정된 공격자 사이에 작은 잔여 겹침이 가능하다.
- 영웅 중심 접근 여유는 `적 반경+.28+.12m`다. walker는.70m를 목표로 바깥쪽으로 점진적으로 보정한다. 경계 허용오차.015m를 두며 안쪽에 합성 배치된 적은 즉시 공격 전조를 만들지 않고 유효한 자리를 찾는다. 이미 지불된 공격·플레이어 이동·돌진에는 이 여유를 소급 강제하지 않는다.
- 겹치는 몸체의 공격 자리 예약은 몸체 반경 합의92%를 경계로 한다. windup/recover/dash/빙결된 몸체의 자리는 고정된다. 움직이는 몸체끼리는 영웅에 가까운 몸체가 먼저 자리를 주장하고 거리차.001m 이내면 낮은 UID가 우선한다. 모든 접근자가 서로 비우기만 기다리는 모서리 교착을 막는다. 뒤의 몸체는 계속 접근·분리한다.
- windup의 위치/방향·회복 위치·빙결 위치와 남은 시간·활성 돌진 궤적은 군중 압력으로 바뀌지 않는다. 새 공격 시작 전 접근 위치를 결정한 뒤 그 위치에서 기존 전조/실제 판정을 시작한다. 빈 전조를 바로 읽던 과거 합성.5m fixture는 새 유효 거리와 충돌하므로 **새 사본만.75m**로 바꾸고1.16m 실제 외곽 판정을 유지했다. 원본 테스트와 코어03 증거는 그대로 둔다.

`crowd_neighbor_checks`는 누적 검사 수, `crowd_peak_neighbors`는 한 접근의 최대 검사 수, `crowd_adjustments`는 순수 직진과 달라진 접근 수다.32개 이후의 몸체를 추가 검사하는 전체쌍 보정은 하지 않는다. 공격/빙결/회복 몸체는 접근 조회를 하지 않지만 움직이는 다른 몸체를 막는 기준으로 읽힌다.

검증은 새 `semantic_regression.gd`, `test_crowd.gd`, `corner_diagnostic.gd`, `normal_pilot.gd`를 사용한다. 앞의3개는 합성 fixture이며 일반 플레이로 표시하지 않는다. 정상 pilot은 기존 이동·회피·선택·소유 장비 장착 입력을 복사하고 요청된 seed71/90131만 사용한다. 기존 seed907과 같은 표본으로 합치지 않는다. HP/XP/아이템/소환/킬 주입·실패 후 seed 교체·승리용 수치 조정은 없다. 실제 실패도 저장하며 전승 여부와 기능검사 통과를 분리한다.

이 코어의 대표 조우는 기존70초 정예와 실제 처치 종료다.5–8분 전체1장·연결 구역·고유 보스·저장 완료, SACRATA 표현/재미 승인, 실제 사용자 플레이, GPU 성능·누수0·실청취를 뜻하지 않는다.
