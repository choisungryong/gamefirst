# UI 개선 계획

## 목표와 디자인 방향

‘금기 서약의 회랑’: 탄화한 석재, 어두운 가죽, 닳은 황동, 붉은 생명 인장. 장식은 생명·기술·희귀도·선택의 위계를 설명할 때 사용한다. 화면 전체를 동일한 갈색 사각 패널로 채우지 않는다. 전투 중앙은 열린 상태로 유지한다.

제목은 한국어 명조 계열, 본문·수치는 읽기 쉬운 고딕 계열을 사용한다. 초기에는 기존 SystemFont 경로로 시안을 만들고, 최종 폰트는 라이선스와 실제 한국어 글리프를 확인해 포함한다. 색과 크기 계약은 UI-DESIGN-TOKENS.json을 따른다.

## U1 — 세 화면 시안과 공통 테마

구현: 현재 HUD의 실제 내용으로 전투, 성장, 장비 비교 시안을 만든다. 생명은 좌하단 인장형 표시+현재/최대값, 하단 중앙은 습득한 기술3슬롯과 레벨/XP, 우측은 회피·회복약을 둔다. 목표는 짧은 현재 행동과 진행량으로 묶는다. 상세 정보는 장비/일시정지 화면으로 이동한다. 이 게임에는 마나가 없으므로 마나 구슬을 추가하지 않는다.

복사할 근거: chapter1/view/cloister_hud.gd:125–156의 _style/_label/_bar/_button, equipment_sigil_quality35.gd:3–17의 자체 슬롯 아이콘. 새로운 버튼의 normal/hover/focus/pressed/disabled 상태를 모두 정한다.

확인:720p와1080p에서 한국어 본문이 읽히고 긴 이름/수치가 잘리지 않는 세 화면. 색뿐 아니라 형태·아이콘·텍스트로 속성과 선택을 구분한다. 시안 자체를 제품 적용으로 기록하지 않는다.

가드: 새 장식마다 복잡한 프레임·광택 애니메이션을 반복하지 않는다. 원본37파일을 덮어쓰지 않는다.

## U2 — HUD·목표·입력 연결

구현: 새 HUD successor를 추가하고 활성 뷰의 HUD preload만 연결한다. 실제 HP/XP·랭크·진화·회피·회복약·목표를 읽는다. 목표 위치 안내는 우선 세 구역의 연결을 나타내는 작은 경로도로 설계한다. 실제 상세 지형/안개 데이터를 만들기 전에는 상세 미니맵으로 표현하지 않는다.

복사할 근거: cloister_hud.gd:158–195의 sync, chapter_hud.gd:20–32의 objective, chapter_run_stun36.gd:301–313의 objective/snapshot. 입력 신호는 chapter_view.gd:49–69의 기존 연결을 그대로 사용한다. 키보드 포커스는 공식 Godot4.5 Control/grab_focus와 focus_neighbor 지침을 읽고 구현한다.

확인: 이동 클릭과 HUD 클릭이 섞이지 않음, Esc/I로 원래 상태 복귀, 메뉴 최초 포커스/모달 닫힘 후 포커스 복구, 생명/XP/목표와 실제 코어 일치. 게임패드 전체 지원은 별도 입력 구현 전 광고하지 않는다.

가드: 매 프레임 전체 전투 snapshot을 복사하지 않는다. 비공개 _next_cast를 UI 계약으로 고정하지 않는다. 쿨다운 링이 필요하면 작은 읽기 전용 표시 계약을 먼저 정의한다.

## U3 — 성장·장비·보상 흐름

구현: 성장 카드는 ‘새 기술/강화/진화’, 핵심 변화량, 짧은 효과 설명을 구분한다. 선택 버튼은 한 곳으로 통일한다. 장비는 현재와 선택 장비, 슬롯·등급·실제 차이를 같은 순서로 보여준다. 승리/패배 화면은 획득물·저장 상태·다음 행동을 명확히 한다. 초상 연출은 캐릭터 계획의 자산이 준비되면 이 구조에 넣는다.

복사할 근거: cloister_hud.gd:237–239의 offer.token/card.id 캡처, chapter_hud_quality17.gd:57–96의 compare_item/equip/scroll 복원, quality20.gd:12–68의 드롭 알림 큐, chapter_hud.gd:43–53과 chapter_one_view.gd:43–52의 저장 상태. 실제 _elite_reward_uid 보상 흐름을 유지한다.

확인: 선택 한 번만 적용, 이전 화면의 클릭이 새 선택으로 넘어가지 않음, 긴 옵션 스크롤 복원,4슬롯 비교, 저장 실패와 재확인 표시. rawHP·bps 등의 표시 단위를 중앙 변환해 옵션과 생명 합산의 반올림 차이가 혼란을 주지 않게 한다.

가드: 장비의 가짜 총점·가짜 희귀도·가짜 보상을 만들지 않는다. UI가 피해·장착·보상 저장을 직접 계산/지급하지 않는다.

## 최종 확인

구현은 기존 신호와 공식 UI API에 맞는지 확인한다. 시각 변경은720/1080 실제 화면으로, 입력 변경은 해당 기능으로 확인한다. 모달·선택·장비·저장 회귀와 성능은 통합된 최종 후보에서 수행한다. 색 수정마다 전체 검사를 재실행하지 않는다.
