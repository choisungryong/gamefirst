# 후보38·제작실 구현 검토

2026-11-11. 범위는 후보38 HUD와 제작실 변경이다. 냉기39는 별도 검증 중이므로 이 판단에 포함하지 않는다.

**판정: 이 구현 단계의 커밋을 막는 결함 없음.** 최종 게임 품질·완주·음향 승인과는 구분한다.

## 확인한 사항

- UI38은 HUD36 상속을 유지한다. 새 조립 변경은 HUD preload 한 줄이며 코어·피해·보상·장착 계산을 변경하지 않는다. 생명은 실제 raw HP에서, XP는 기존 성장 임계와 바에서 읽는다. 장비 차이는 실제 선택/현재 장비의 속성 차이다.
- 성장 선택의 기존 token/callback을 유지하며 모달의 활성 버튼에 Tab 순환과 첫 포커스를 연결한다. 장비 상세 스크롤과 기존 장착 신호도 유지한다. 실제 패키지 Forward+ 22개 통합 확인은 기존 원시 결과를 검토했으며 불필요하게 재실행하지 않았다.
- 제작실 경로는 프로젝트 안의 카탈로그 허용 파일로 제한되고 경로 순회·저장·자격증명 경로를 차단한다. 서버는 loopback 바인딩이며 쓰기 Host/Origin을 확인한다. 요청 revision 충돌은409로 반환하고 메모는 임시 파일과 원자적 교체로 저장한다.
- 제작실은 게임 수치와 사용자 플레이 저장을 편집하지 않는다. 현재 후보38 선택에는 성공한 통합 결과·PCK 감사·EXE 크기/SHA가 필요하며, 미완성 패키지는 후보37로 유지한다. 요소 종류와 구현/에셋 등록 수를 구분한다.
- 모델 뷰어는 로컬 번들이며 미리보기 URL을 로컬·blob·data로 제한한다. 없는 Meshopt 디코더의 즉시 요청을 제거한 수정도 확인했다.
- staged 목록에 사용자 profile/local-state/실행 파일/화면 캡처/.godot 캐시가 포함되지 않았다. `git -c core.whitespace=cr-at-eol diff --cached --check` 통과.

## 발견 및 수정한 결함

`tools/game_manager/app.js`에서 재생 중 다른 애니메이션을 선택하면 실제 모델은 정지했지만 버튼이 ‘일시 정지’로 남았다. 클립 변경 시 버튼도 ‘애니메이션 재생’으로 복원했다. `node --check tools/game_manager/app.js` 통과.

실제 브라우저에서 주인공 GLB 로드 → cast 선택 → 재생(‘일시 정지’ 표시) → run 선택(‘애니메이션 재생’ 복원)을 확인했다. 원시 화면은 `proof/manager-animation-switch-20261111.png`다. 검사 탭은 닫았고 CUA 완료 요약도 처리했다.

게임 소스·후보38 freeze·프로필·실행본에는 수정하지 않았다. app.js 수정은 최종 커밋 전에 stage 갱신이 필요하다.
