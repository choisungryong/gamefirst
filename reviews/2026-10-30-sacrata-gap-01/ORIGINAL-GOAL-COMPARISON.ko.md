# 원래 REA·D2R 개발 제안과 현재 결과의 재대조

2026-10-30, Asia/Seoul. 사용자가 제시한 원래 제안문을 현재 증거와 앞선 SACRATA 품질 분석(REPORT.ko.md)에 다시 대조했다. 이번에는 새로운 D2R 디컴파일·실행 관찰·설치·제품 변경을 하지 않았다. 아래 D2R 버전·분석 성공/실패는 보존된 기록의 사실이다.

## 결론 보완

앞선 보고서의 전투 밀도·성장·아트 미달 판정은 유지한다. 여기에 더 근본적인 문제가 있다. 원래 요청은 D2R 시스템의 동작과 설계 원리를 근거로 정리하고 SACRATA형 군중 전투·파밍·빌드로 재설계하는 것이었다. 실제 구현은 제한된 표/클래식 참조를 바탕으로 매우 작은 독립 전투·장비·성장 검증판을 만들고, 그 위에 짧은 원정을 붙이는 방향으로 축소됐다.

따라서 수정 방향을 단순히 더 많은 적·성장 카드·좋은 모델 추가로만 설명하면 부족하다. `원문 근거 → 검증된 규칙/미확인 경계 → 채택할 설계 원리 → 뱀서류용 변경 이유 → 플레이에서 확인되는 변화`의 연결을 다시 갖춰야 한다. 독립 구현의 규칙도 원래 분석 질문 및 제품 목표와의 연결이 필요하다.

## 원래 제안에서 그대로 유지할 점

1. D2R 전체 엔진 복원을 게임 개발의 선행 조건으로 삼지 않는다.
2. 공개 참조·추출 데이터·관찰로 답을 얻고, 남는 특정 질문에 REA를 사용한다.
3. 출처와 확실성을 분리하고 독립적인 규칙 명세를 만든다.
4. 군중 전투용 갱신·검색·충돌·pool·표현 예산은 자체 엔진 구조에 맞게 설계한다.
5. 원작 코드·아트·소리를 제품으로 옮기지 않는 현재 작업 경계를 유지한다. 현재 원정 패키지의 연구 이미지 제외 기록은 보존한다.

## 원래 설명에서도 보정할 점

- **가능성 평가와 성공 결과:** “매우 높음/높음”은 분석 가능성의 일반 판단이다. 대상 빌드의 의미 확인·입력/출력 재현·반례 검증이 있어야 실제 확보한 범위를 말할 수 있다.
- **D2MOO의 버전:** 공개 저장소 README는1.10f 기반이라고 명시한다. 현재 D2R 함수의 증거가 아니며, 고정 커밋의 클래식 참조로 사용한다. https://github.com/ThePhrozenKeep/D2MOO
- **자료 경로:** 원작MPQ 설명을 D2R에 그대로 적용하지 않는다. 현재 연구는 D2R CASC에서 별도로 추출한 표를 사용했다.
- **REA 역할:** REA는 분석 엔진과 연결해 특정 함수/관계를 조사하는 수단이다. MCP 연결·PE 읽기만으로 규칙이 복원되지는 않는다. 현재 성공하지 못한 전체 엔트리 분석을 그대로 반복하는 것이 다음 작업은 아니다. https://rea.tools/guides/
- **전투 규모 설명:** D2를 소수 몬스터만 전제한 게임이라고 일반화하지 않는다. 새 게임이 요구하는 동시 활성 수·공격 형태·갱신 비용·카메라·입력 정책을 별도로 정의하는 것이 정확하다.
- **단계 분리:** 다섯 단계를 모든 연구가 끝날 때까지 개발을 멈추는 거대한 순차 과정으로 운영할 필요는 없다. 시스템별 질문 단위로 분석→검증→명세→구현을 닫고, 근거가 확정된 기능과 아직 미확인인 기능을 명확하게 구분한다.

이 표는 새로운 연구·설계 과제이며 이번에 복원/구현했다고 주장하지 않는다. 각 질문은 먼저 기존 표·고정 클래식 참조·정상 동작 관찰에서 답을 찾는다. 현재 D2R의 특정 함수 확인이 반드시 필요한 차이만 REA의 함수·xref·상수·호출자 조사 대상으로 삼고, 실패시 미확인으로 남기는 종료 기준을 둔다.

## 다음 완료 기준

수정된 RPG 설계는 대표60–90초의 실제 플레이에서 검수한다. 분석 문서에만 존재하는 시너지, 화면에서 변화가 없는 성장, 의미가 반복되는 드롭은 통과시키지 않는다. 예를 들어 서로 다른 두 성장 선택이 공격 범위/위험 대응/아이템 우선순위를 바꾸는지, 적 유입과 처치가 압박과 해소의 흐름을 만드는지, 같은 카메라 거리에서 캐릭터·적·효과·지형을 읽을 수 있는지를 확인한다.

이는 두 개의 별도 관문이다. D2R 연구→독립 RPG 설계가 연결되어야 하며, 동시에 SACRATA 지향의 전투·아트 품질을 실제 장면으로 입증해야 한다. REA를 더 사용한 사실이나 새 모델을 붙인 사실만으로 어느 관문도 자동 통과하지 않는다.
